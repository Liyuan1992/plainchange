# 为什么这样改：任务对话层视觉规格

目标：让不会代码的用户先知道“系统已经有线索”，再按需查看线索来自谁；不能把 AI 的解释冒充用户意图。

## 默认态

- “为什么这样改”使用蓝色`已有对话线索`状态，不使用表示故障或无证据的灰色 unknown。
- 正文只说明已找到用户任务和 AI 回复，不直接把两者合并成结论。
- 按钮为`查看已有任务线索`，旁边明确`不调用模型，不消耗额外 Token`。
- 任务摘录在用户点击前不可见。

## 展开态

- 当前摘要卡跨两列，其他摘要卡保持原顺序。
- 用户原话和 AI 回复并排，使用不同但克制的边框色。
- 每张卡同时显示角色和来源；AI 卡显示`不能代替用户确认`。
- 底部用一条短规则解释判断顺序。
- 390 px 下两张卡改为单列，页面无横向滚动。

## 边界

- 当前正式报告是离线单文件，只展示已冻结线索，不伪装成可以读取 Codex 任务或调用模型。
- 产品未来的`从任务窗口提炼`按钮属于连接态合同，必须标明需要 Token，并由用户点击触发。
- 复用既有 22 个设计 Token，不新增视觉体系。
