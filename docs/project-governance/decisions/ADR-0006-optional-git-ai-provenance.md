# ADR-0006：以可选只读适配器接入 Git AI 代码来源记录

- 状态：已接受
- 日期：2026-09-12
- 决策人：项目负责人
- 关联任务：`TASK-20260912-060`

## 背景

PlainChange 已能固定一次 Git 变化、解释软件影响并保留验证未知项，但“用户需求或 AI 会话如何对应到具体代码”仍是断开的。Git AI 已经负责记录代码来源；PlainChange 没有必要复制它的 checkpoint、hooks 和会话存储。

Git AI 的机器可读范围输出同时可能包含提示词记录、会话标识、邮箱、会话地址、提交正文、完整 diff 和旧文件内容。直接保存或转交这份 JSON 会突破 PlainChange 的最小披露与模型输入边界。

## 决策

1. 新增统一的 `AgentProvenanceProvider`，首个实现只适配 Git AI。
2. PlainChange 只检测已经存在的 `git-ai` 可执行文件，不自动安装、不增加 hooks，也不修改目标仓库。
3. 对固定的 base/head 只执行 `git-ai diff <base>..<head> --json`。调用使用固定参数数组、`shell=False`、超时、输出大小上限、禁用 Git 可选锁和终端提示。
4. 当前 Git AI 的 `stats` 是单提交口径，不能作为任意 base/head 范围汇总。因此范围统计从同一份 `diff --json` 的 additions/deletions 和来源字段计算，并与 PlainChange 已确认的 Git 行数核对；不混合两个统计口径。
5. 只持久化归一后的数量、相对文件路径、脱敏工具/模型、记录数量、状态、限制和 SHA-256。原始提示词、会话/人员标识、邮箱、会话位置、提交正文、diff 和 base 内容立即丢弃。
6. 新增独立权威类型 `authorship_attestation`。它只能回答“代码来源记录了什么”，不能升级为用户意图、功能正确、测试通过、运行事实或用户影响。
7. 未安装、没有记录、部分记录和无效记录都不会阻止 PlainChange 主报告生成。无效数据失败关闭，不能退化成未经校验的文本展示。

## 后果

- 已经使用 Git AI 的项目可以在同一份 Change Passport 中看到代码来源摘要，同时保留 PlainChange 的影响与验证边界。
- 未使用 Git AI 的项目仍可正常分析；报告只说明未来可以开始记录，不能补造过去的来源。
- M1 不读取完整会话，所以“用户原话到某段代码”的语义联系仍需后续、单独批准的隐私与证据设计。
- Git AI JSON 合同变化可能让记录进入 `invalid`；这是有意的安全降级，需要通过适配器版本更新解决，不能猜测兼容。

## 批准依据

项目负责人确认“现在打算接入 Git AI”，并在收到上述只读、可选、隐私受限的实施规格后明确回复“确认”。
