## 实际发现与反证

### VideoFactory：保留四项疑似风险

1. **声音输入变化后仍可能复用旧配音。** `tts/synthesizer.py:22-34` 的复用摘要
   包含文字、语速和路径，未包含种子、采样率或引用音频的内容；`89-118` 显示
   摘要匹配便跳过合成。独立静态复核支持遗漏事实，具体音频后果尚未运行验证。
   原来的“固定音频同路径替换”候选被合并，避免重复列问题。
2. **时间线复用可能遗漏输入。** `pipeline.py:51-55` 只比较配音清单摘要，
   `timeline/build.py:31-49` 还使用混音参数、字幕长度和声音增益。
   必须限定“配音清单保持不变”的前提；不能把所有停顿改动都说成必然不更新。
3. **单独渲染与验收可能不衔接。** `cli.py:250-256` 直接调用渲染；
   `render/pipeline.py:117-136` 保存的清单没有完整构建在 `pipeline.py:106-110`
   补写的三项签名，而新鲜度判断要求这些签名。完整构建路径不能替代单独命令的验证。
4. **旧画面审阅意见可能进入新版。** `qa/review.py:120-162` 校验格式、场景和意见，
   未见与具体画面版本绑定的检查。它仍是使用前提明确的风险，不能据此说实际交付已经出错。

### DigitalSelf：撤回两项，保留一项疑点和一项证据缺口

- 初稿怀疑并发会话串用。补读 `core/chat_engine/turn_state.py:30-71` 后，
  发现属性背后是 ContextVar 任务局部状态，撤回基于“共享字段”的推断。
- 初稿怀疑失败回复在界面显示为成功。补读消息详情和已有状态处理后，
  发现界面处理 failed 交接状态，撤回该推断。
- 保留发送异常后的草稿恢复疑点。独立检查 `composer.js:318-393` 可见清空输入后发送；
  但用户文字已经显示在聊天记录中，不能声称信息彻底丢失。异常时序、附件恢复和发送确认
  仍需隔离运行验证。报告所引片段未涵盖发送调用的最后数行，是本轮仍留下的语义引用局限。
- 保留长期记忆最终状态的**证据缺口**。后台写入与回复分开是正常设计，
  本轮没有覆盖全部回执入口，不能断言产品没有回执或记忆丢失。

### memdsl：两项初始候选均撤回

“无查询结果仍成功退出”有结果内容和独立状态解释；“强制批准”是显式操作选项，
普通批准仍会拒绝。这些片段不足以证明缺陷，不能为了让报告显得有用而强行保留。
零项保留只说明本次阅读没有形成可靠候选，不是项目无缺陷证明。

### memdsl 完整命令复验：更深阅读带来三项新候选

最终运行更新后的 `plainchange understand` 完整命令，包含 11 次真实模型请求，
读取同一提交的 17 / 53 个文件、48 段源码，成功生成报告。它比对照样本多读了实现，
保留了并发人工批准的过时工作区、普通提案写入后的模块校验语境、兼容查询未应用
返回字节上限三项疑点。它们尚未运行复现，不能称为三项确认缺陷。

尤其是返回字节上限：`mcp_server.py:137-148` 接收参数，`mcp_service.py:717-799`
的两条路径处理不同，疑点具有明确的输入和观察办法。并发批准仍需实际交错执行验证；
提案语境问题还可能被其他检查器拒绝，报告已列出这些反例。

本轮交付入口使用这份较深的 memdsl 报告，同时保留先前对照。三份主报告共 9 项
待核查内容（8 项疑似风险、1 项证据缺口）。**不同生成会选择不同片段，不能把一次
没发现问题当作质量结论；也不能用本轮样本直接计算准确率或召回率。**

该完整运行的 11 份提供器回执累计 498.13 秒、971,835 个输入 token 和 19,913 个
输出 token（提供器报告值，含重复上下文；不是独立源码大小或金额账单）。使用已登录
Codex 的订阅额度，未切换付费 API。当前延迟和重复上下文成本仍明显，更适合按版本
做深入审阅；不能声称即时理解或已经完成增量缓存优化。

## 对 PlainChange 的改进与仍需面对的问题

已加入通用的两轮反证选读：检查调用者、属性实现、请求隔离、错误处理、缓存和版本边界。
候选逐项映射为保留、修订或撤回，并保留代码依据。模型不能新增“已确认缺陷”状态，
也不能把未执行的核查升级为通过。

VideoFactory 初次产品解读把一处引用写为 275..30，校验拒绝了报告；原始失败产物保留，
反证审阅修订后的结果重新通过严格引用校验。没有静默裁剪行号或编造来源。

这一轮最有价值的发现是：**有引用不代表推断成立**。反证阶段确实找到了能推翻
初稿的实现，但仍由同一模型完成，不能称为独立证实。报告仍可能漏读关键实现，
或用邻近代码引用支撑超出该行范围的措辞。需要继续保留独立源码复核和实际运行验证。

普通读者首屏不再首先面对模块和函数清单，但完整报告较长；测试应观察能否找到所需信息，
而不能只看“所有内容都写进去了”。五问材料见 [理解测试](TASK-043-reader-test.md)。
