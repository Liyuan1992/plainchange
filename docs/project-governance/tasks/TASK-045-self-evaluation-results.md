# PlainChange 自测：当前版本能否让人放心使用

日期：2026-09-20。对象是当前未提交实现的隔离快照
`4636b390684cce2112acff6c023fce642b6ee9ac`，并非原仓库发布提交。
原有工作未覆盖；本轮只做诊断和记录，不修改产品实现。

## 已确认的问题

### SELF-01 / 高优先级：正常分析可能因一次越界读取请求而整体失败

真实运行 `plainchange understand` 分析自己的第 5 轮请求了
`src/plainchange/templates/onboarding.html`。文件存在，但 HTML 不在
`system_flow.py:23` 的允许扩展名中；`system_flow.py:433` 遇到清单外路径
直接抛错，最终无 `review.html`。原始请求和 failed 收据已保留。

拒绝越界读取是正确的；产品缺口是没有把拒绝结果交回模型进行有界纠正，
也没有阶段续跑入口。用户要为无结果的分析等待并重新消耗订阅额度。
首轮共 5 次模型请求，提供方收据累计 58.8 秒、272,977 输入 token
（包含缓存口径，不能据此推算账单或实际额度扣除）。
HTML 模板的排除同时限制了对页面入口、文案和布局的理解。不能因此直接
放宽所有文件读取；应保持清单约束并增加明确拒绝反馈与受限恢复。

### SELF-02 / 高优先级：本地服务没有验证 Host 是否可信

真实 HTTP 连接始终指向 127.0.0.1 测试服务。传入 `Host: selftest.invalid`
仍获得首页及会话 token；随后用同名 Host/Origin 和该 token 调用
`/api/repository` 成功读取合成项目元数据（200）。缺 token 或只有外域
Origin、Host 仍为本机的对照请求均为 403。

`onboarding.py:434` 用请求中的 Host 构造允许 Origin，首页也没有 Host
白名单。已证实的是应用层 Host/Origin 校验缺口；没有执行 DNS rebinding、
浏览器远程攻击或数据外传，不能宣称公网已可利用。应优先固定允许的
loopback Host/端口，并在返回首页 token 前检查。

### SELF-03 / 中优先级：刷新后失去任务和报告入口

通过真实浏览器选择合成项目、生成基础报告、打开成功；返回首页并刷新，
项目路径清空，报告链接和任务状态不再显示，界面重新回到首次使用。
报告文件仍存在，这不是数据丢失，但普通用户没有“最近报告”或“恢复任务”
入口。源码只在页面内存保存状态，服务端虽有 jobs，但页面没有恢复流程。
建议先补最近任务/报告与安全恢复，再增加报告种类。

### SELF-04 / 中优先级：没有验证收据时仍显示“已完成检查”

真实打开本轮基础报告，页面同时出现“✓ 已完成检查 / 已经替你验证”与
“这份报告没有收到结构化验证收据”。正文说明没有捏造测试结果，但正向
图标和标题先传达了完成感，可能误导快速浏览的负责人。
对应 `templates/review.js:275`、`:279`。这是可复查的呈现矛盾；
尚无真人误读率证据。零收据时应采用“尚无验证记录”等中性标题。

### SELF-05 / 较低优先级：部分非法 API 参数导致断连接

授权本地请求向 `/api/understand` 传入对象类型 output，服务端抛出
TypeError，客户端得到 RemoteDisconnected，而不是 JSON 400。
输出指向项目内部的对照请求能正确返回 400；主进程仍可服务。
此输入不是现有页面的正常输出，影响主要在 API 健壮性与错误恢复。

## 已通过的部分

### SELF-06 / 高优先级：并发任务互相覆盖需求与产物（自评报告候选已复现）

自评报告反证后保留的 `concurrent_output` 用真实管线复现：相同项目、版本
和输出目录同时提交两项基础分析，需求分别为 request-alpha、request-beta。
alpha 任务 succeeded，beta 任务因 `run-receipt.json.tmp` 重命名冲突 failed；
但最终 guided-manifest.json、evidence.json、generator-packet.json 中保留的
需求都是 request-beta。成功任务没有可靠对应自己的需求，属于可信度问题。
证据：probe_concurrent.py、concurrent-results.json、concurrent-stderr.txt 及
concurrent-report/。没有 mock 模型或进度写入。单任务对照已通过。
应优先增加任务级输出隔离或同目录互斥，并绑定不可变输入与结果身份。

### SELF-07 / 解析质量缺口：自评遗漏了独立“理解系统”入口的完整路径

第二轮成功报告的五问、使用旅程和四条流程主要解释“两版本变化分析”。
它确实读到了 system_flow.py、product_review.py 和 onboarding.js，但没有
单独讲清“无需两个版本、用 Codex 生成系统地图”的主流程。实际页面已验证
存在此入口，任务关注点也包含它。引用可核验不等于主要能力覆盖完整。
报告声明了非穷尽范围，因此不视为伪造；仍会降低用户通过报告理解当前
产品的完整性。建议检查入口覆盖并明确列出未解释的主要能力。
