# TASK-20260912-060：接入 Git AI 代码来源记录

状态：DONE
风险等级：标准
日期：2026-09-12
领域：AI 代码来源

## 产品决策

PlainChange 需要连接目前断开的证据链：

`用户需求 → AI 会话 → 修改的代码 → 软件影响 → 验证结果`

Git AI 负责记录代码由谁产生，PlainChange 负责读取这些记录，并向软件负责人解释一次变化的来源和范围。PlainChange 不重新实现 Git AI 的记录机制，也不能把“代码来源记录”说成“软件功能已经正确”。

## 当前情况

- PlainChange 可以接收用户手工填写的任务背景，也能解释固定的 Git 变化，但还不能自动建立 AI 会话与代码行之间的对应关系。
- 当前电脑尚未安装 `git ai` 命令。
- Git AI 已提供可供程序读取的范围命令：`git ai diff <较早版本>..<较新版本> --json`。实施核对发现当前 `stats` 是单提交口径，不能直接作为任意前后版本范围的汇总。
- Git AI 把代码来源记录放在 `refs/notes/ai`，完整会话保存在 Git 仓库之外。
- Git AI 当前的代码来源标准版本为 `authorship/3.0.0`。工具、模型或会话字段可能缺失，也可能显示为未知，因此不能把这些身份信息当成始终完整可靠的事实。
- PlainChange 当前工作区干净，本地分支比 `origin/main` 多一个尚未推送的提交。

## 确认后实施的范围

### 一、可选的来源提供器

新增统一的“AI 代码来源提供器”接口，并实现 Git AI 适配器。

PlainChange 只检测本机是否存在 `git ai`，不会自动安装 Git AI，也不会修改 hooks。检测到 Git AI 后，只针对已经固定的前后版本调用官方只读 JSON 命令。Git AI 未安装或没有历史记录时，PlainChange 仍然正常生成报告。

### 二、严格区分证据类型

Git AI 返回的所有数据都必须先经过格式、大小和字段校验，才能进入 PlainChange 证据包。

记录内容包括：

- 前后 Git 版本；
- Git AI 版本（能够获得时）；
- 使用的命令合同版本；
- 规范化结果摘要；
- 结果哈希；
- 已记录、人工和未追踪代码行数量；
- 成功或失败状态。

新增独立证据类型：`AI 代码来源记录`。它不能升级为以下任何一种证据：

- Git 已确认事实；
- 实际运行验证；
- 独立测试结果；
- 用户影响已经确认。

需要支持五种状态：

- `已有记录`：至少一行变化代码有有效来源记录。
- `部分记录`：存在有效记录，但仍有代码行没有来源或身份未知。
- `没有记录`：Git AI 可用，但所选变化范围没有来源数据。
- `尚未安装`：本机没有 Git AI。
- `记录无效`：输出格式错误、过大、版本不支持，或无法与本次前后版本绑定。

### 三、隐私和模型边界

M1 阶段不得：

- 调用 Git AI 的 `/ask`；
- 打开会话链接；
- 查询 Git AI 的本地会话数据库；
- 把完整提示词、工具参数或完整会话发送给用户配置的大模型。

模型最多只能收到经过限制的来源摘要，例如：AI 工具名称、能够确认的模型名称、数量和相关文件路径。

默认报告不展示原始会话 ID、邮箱和会话存储位置。确需保留技术关联时，只保存脱敏值或不可逆哈希。

所有 Git AI 字段都按不可信外部输入处理。未经转义和格式校验，不得进入 HTML、Markdown、命令参数或大模型提示词。

### 四、普通用户看到什么

在“这次改了什么”页面增加一个简洁区域：

> 这次改动从哪里来

其中展示：

- 记录到的 AI 工具和模型；
- 参与修改的会话数量；
- AI、人工和未追踪代码的覆盖范围；
- 明确提示：“来源记录不能证明功能正确。”

来源摘要可以跳转到现有变化图和系统流程图。技术详情中可以展示文件和代码行范围，但默认页面不能变成面向管理者的“AI 代码占比仪表盘”。

Git AI 未安装时，不显示吓人的错误。页面只说明：

> 这次变化没有记录 AI 来源。安装 Git AI 后，可以从未来的变化开始记录；以前没有记录的变化不能自动补回。

### 五、验证要求

- 使用可控的模拟命令完成自动化测试，正常测试不能依赖本机已经安装 Git AI。
- 覆盖以下情况：AI、人工和未追踪代码混合；没有数据；没有安装；执行超时；JSON 错误；结果过大；模型未知；危险文本；命令失败。
- 证明目标项目和 `refs/notes/ai` 在分析前后完全不变。
- 证明完整会话、原始 ID、邮箱和密钥不会进入模型输入或默认报告。
- 验证中英文界面、桌面和窄屏布局、报告数据完整性、完整测试、Python 包构建和 Windows 便携版构建。
- 只有在用户单独授权安装和配置 Git AI 后，才进行真实 Git AI 采集测试。
- 真实测试必须分别记录：来源采集是否成功、PlainChange 是否成功生成报告、用户是否认可最终表达。三者不能混为同一项结果。

## 本阶段明确不做

- 不复制或修改 Git AI 源码。
- 不实现 Git AI checkpoint、Agent hooks 或会话存储。
- 不调用 `/ask`。
- 不实现团队遥测、费用分析、PR 仪表盘或自动安装 Git AI。
- 不把 AI 来源记录说成需求、正确性、测试通过或运行影响的证明。
- 不针对 PlainChange、Codex、Claude Code 或任何样本项目写特殊规则。
- 未经单独授权，不推送代码、不发布安装包，也不创建新的 GitHub Release。

## 确认门

用户已于 2026-09-12 明确回复“确认”，批准按本规格实施第一阶段。

第一阶段交付物是：可选的只读 Git AI 适配器，以及面向普通用户的“这次改动从哪里来”说明。Git AI 安装、hooks 和读取完整会话属于后续独立阶段，需要再次确认。

## 实施结果

- 新增 `AgentProvenanceProvider` 与 `GitAIProvenanceProvider`。默认只检测 `git-ai`，不会安装、配置或修改目标项目。
- 使用固定参数数组读取 `git-ai diff <base>..<head> --json`，带超时、8 MiB 输出上限、禁用 Git 可选锁与终端交互。
- 来源行数直接从同一范围输出的 hunks 计算，并与 PlainChange 已确认的 Git 新增/删除行数核对；没有混用单提交 `stats` 口径。
- 新增 `plainchange.agent-provenance.v1` 归一化产物及 SHA-256。默认只保留固定版本、状态、数量、相对文件路径、脱敏工具/模型和记录数量。
- 原始提示词、会话地址、会话/人员 ID、邮箱、提交正文、完整 diff、旧文件内容和 stderr 均不会进入产物、模型上下文或 HTML。
- 生成器只接收一条有边界的 `authorship_attestation` 摘要；它不能成为 Git 事实、任务意图、测试、运行或用户影响证据。
- “这次改了什么”增加中英文“这次改动从哪里来”，支持已有、部分、无记录、未安装和无效状态；窄屏改为单列。
- 重新应用报告译文包时会保留同一来源摘要。
- README 中英文版、Changelog、证据合同与 ADR-0006 已同步。
