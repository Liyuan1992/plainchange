# TASK-20260912-064：把验证证据变成负责人可直接使用的控制面

状态：DONE
风险等级：标准
日期：2026-09-12
领域：负责人体验、证据合同

## 用户问题

当前 Git AI 接入自分析虽然没有越过证据边界，但负责人仍然不知道具体改了
什么、为什么说还没验证、已经替他验证了什么，以及剩下应该由谁完成。页面
把静态未知项和工程检查原样交给用户，未能减少决策负担。

## 目标

- 把真实测试、构建、浏览器或集成实验收据作为固定版本绑定的结构化证据。
- 首页先展示具体变化，再分别展示“已经替你验证”“还没验证及原因”和
  “只剩你需要决定什么”。
- 每个未验证项必须给出原因、最小验证方法和责任归属；工程检查不能伪装成
  软件负责人的手工任务。
- 用 PlainChange 自身 Git AI 接入重新生成报告，负责人无需阅读技术术语即可
  复述变化、已验证项和剩余决策。

## 非目标

- 不自动执行目标仓库中的任意测试或构建命令。
- 不把测试通过升级为生产运行、长期兼容或用户影响证明。
- 不为 PlainChange、Git AI 或某个仓库增加名称匹配特例。
- 不改变第二个 Tab 的架构证据合同。

## 实施计划

1. 增加受限、哈希绑定的验证收据合同，并允许现有
   `test / actual_test_receipt` 证据携带该结构。
2. 将验证收据透传到 validated brief、beginner review 和离线 HTML；来源文本
   仍受原有限额，未知结构不进入负责人验证面板。
3. 从结构化收据和现有 unknown claim 的 `limitations / next_check` 生成负责人
   验证控制面；只显示有证据的通过项，不发明结果。
4. 重构变化首页的信息层级，并补齐中英文投影与响应式样式。
5. 为 Git AI 接入历史验证生成固定身份收据，重跑模型报告并做桌面/窄屏截图
   验收。

## 验收

- 首屏用“以前不能做什么 / 现在可以做什么”说明 Git AI 接入。
- 已验证区显示真实测试、构建、Windows、原生来源链路和隐私检查。
- 每个“还没验证”同时显示原因和如何验证，不再出现裸的工程术语清单。
- 页面明确告诉负责人本轮是否还需要亲自运行命令。
- 收据版本不匹配、超限、身份不匹配或未知字段时失败关闭。
- 完整测试、构建、桌面与窄屏浏览器检查通过。

## 批准依据

项目负责人确认现有报告没有减轻其负担，并明确回复“是的，你来改”。这同时
批准上述验证证据和首页决策层级改造；不授权提交、推送或发布。

## 完成结果

- 新增 `plainchange.verification-receipt.v1`：收据同时绑定前后 Git 版本和
  内容哈希，字段、数量、类别、状态与双语文本严格校验，错误时失败关闭。
- 验证收据贯穿 generator packet、validated brief、beginner review 与离线
  HTML；模型提示直接收到结构化收据，不能再把已提供收据说成不存在。
- 第一屏从三张抽象状态卡改为“已经替你验证 / 还有什么没验证、为什么 /
  需要你决定”，通过项展示结论、范围，缺口展示原因、方法和责任方。
- PlainChange 自身 Git AI 接入报告显示 6 项已通过；本任务完成后的完整回归为
  155 项通过，收据固定记录了生成该报告时的测试范围，并同时展示
  Python 包、Windows 便携包、原生 Codex 来源、Windows Git AI 命令发现和
  隐私过滤。模型报告只保留跨项目、Git AI 版本与生产运行边界。
- 修复后又发现并关闭一项证据合并缺陷：被校验器降级到其他 section 的
  测试收据说明，不再被误投影成负责人待办；显式 attention 未知仍保留。

- `uv build`：sdist 与 wheel 成功。
- `scripts/build-windows-portable.ps1`：EXE 与 ZIP 成功。
- `node --check src/plainchange/templates/review.js`：通过。
- 模型报告：`artifacts/plainchange-git-ai-integration-review-v9/review.html`，
