# TASK-20260912-066：让负责人决策直接说清具体未验证事项

状态：DONE
风险等级：标准
日期：2026-09-12
领域：负责人体验、证据合同

## 问题

只要报告存在验证缺口，负责人区域就固定显示“你现在只需要决定 1 件事”和
“是否在剩余验证完成前接受这次变化”。这段模板既没有说明具体缺口，也在
存在多个缺口时错误地继续显示“一件事”，导致不同项目看起来在要求同一个
抽象决定。

## 目标

- 决策标题使用真实剩余验证数量。
- 决策区域逐项列出本项目尚未验证的结果及责任方。
- 明确说明提前接受不会把未验证项升级成已通过。
- 失败检查、仍有缺口和无缺口三种状态保持不同语义。
- 中英文界面文案均由同一结构化决策数据投影。

## 非目标

- 不根据 PlainChange、VideoFactory 或任何仓库名称增加规则。
- 不自动替负责人作出接受、暂停或发布决定。
- 不改变验证收据、事实强度或已有缺口的判定依据。

## 实施与验证计划

1. 从 `failed_checks` 或 `gaps` 生成带数量和具体条目的决策对象。
2. 在负责人决策面板展示条目和责任方，并补充响应式样式。
3. 增加单缺口、多缺口、失败和无缺口回归测试。
4. 重建 PlainChange Git AI 与 VideoFactory 两类报告，确认同一实现产生不同的
   项目决策内容；运行完整测试和脚本语法检查。

## 批准依据

负责人看到跨项目重复模板后要求列出具体内容，并在确认其为通用模板缺陷后
明确回复“嗯，进行修改吧”。这批准本任务的通用修正与回归验证，不授权提交、
推送或发布。

## 完成结果

- 决策对象现在携带中英文标题、边界说明和逐项 `items`；条目直接复用已经
  校验的缺口或失败检查，不从项目名称、文件名或自由文本猜测新结论。
- 单个和多个缺口使用真实数量；每个条目显示具体未验证结果及责任方。
- 提前接受的含义被明确限定为“保留未验证状态”，不会把缺口升级为通过。
- 失败检查生成暂停决策；无缺口时明确没有待补工程检查，三种状态不再共用
  同一句模板。
- 重建的 PlainChange Git AI 报告列出跨项目/生产验证边界；VideoFactory 报告
  列出真实成片、旧结果失效提示和制作人员体验。两份报告使用同一实现但决策
  内容不同。
